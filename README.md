# 3D Product Catalog

Каталог трёхмерных моделей товаров для интернет-магазина.

**Автор:** Дындарь Маргарита Всеволодовна
**Группа:** ИКБО-31-24
**Репозиторий:** https://github.com/tormoznutaya/3dcatalog

## О проекте

Информационная система для подготовки, хранения и публикации 3D-моделей
товаров. Позволяет товароведам формировать заявки на 3D-модели,
дизайнерам — готовить и публиковать модели, а покупателю — просматривать
модели в браузере и искать товары по тегам.

Предметная область и бизнес-процесс «Подготовка и публикация 3D-модели
товара в каталоге» описаны в [`docs/business-process.md`](docs/business-process.md)
и моделируются диаграммой BPMN 2.0 (см. `models/bpmn.png`).

Проект реализован в двух версиях одной и той же программы:

| Версия | Контрольная точка | Язык | Парадигма | Расположение |
| --- | --- | --- | --- | --- |
| Процедурная | КТ2 | Python 3.12 | процедурное программирование | `src/` (кроме `src/java/`) |
| Объектно-ориентированная | КТ3 | Java 21 (LTS) | ООП | `src/java/` |

Обе версии реализуют одни и те же два алгоритма на одних и тех же
тестовых данных и дают посимвольно совпадающий вывод.

## Алгоритмы

Оба алгоритма реализованы в обеих версиях:

1. **Проверка комплектности заявки** (Алгоритм 1).
   Процедурная версия — `algorithms.check_request()` (Python);
   ООП-версия — `validation.CompletenessRule.validate(Request)`
   (реализация интерфейса `Rule<T>`).
   Сложность O(n), где n — число обязательных полей заявки.

2. **Поиск 3D-моделей по тегам** (Алгоритм 2).
   Процедурная версия — `search.search_models()` (Python);
   ООП-версия — `search.TagSearchStrategy.search(...)` (реализация
   интерфейса `SearchStrategy`).
   Сложность O(Q·M·T), где Q — число тегов запроса, M — число моделей,
   T — число тегов модели.

## Запуск процедурной версии (КТ2, Python 3.12)

    cd src
    python main.py

Подробности — в [`src/README.md`](src/README.md).

## Запуск ООП-версии (КТ3, Java 21)

Из корня репозитория:

    javac -encoding UTF-8 -d out $(find src/java -name '*.java')
    java -cp out ru.mirea.kt3.Main

Требуется JDK 17+ (рекомендуется 21 LTS). Сторонних библиотек нет —
только `java.base`. Подробности — в [`src/java/README.md`](src/java/README.md).

## Ожидаемый вывод (одинаковый для обеих версий)

    Заявка валидна: False
    Не хватает полей: ['id_модели', 'дата']

    Найдено моделей: 2
    - Стол (совпадений: 2)
    - Стул (совпадений: 1)

Тестовые данные захардкожены в `src/example_data.json` (Python) и
`Main.loadTestData()` (Java) и совпадают между собой.

## Диаграмма классов (КТ3)

Структура ООП-реализации описана диаграммой классов UML:
[`models/classes.png`](models/classes.png) (исходник — `models/classes.puml`).

Пакеты ООП-реализации (`src/java/ru/mirea/kt3/`):

- `domain/` — классы предметной области: `Product`, `Model3D`, `Tag`,
  `Request`, абстрактный `User`;
- `users/` — наследники `User`: `Merchandiser`, `Designer3D`, `ContentManager`;
- `validation/` — интерфейс `Rule<T>` и реализации `CompletenessRule`
  (Алгоритм 1), `FormatRule`; `ValidationResult`;
- `search/` — интерфейс `SearchStrategy` и реализация `TagSearchStrategy`
  (Алгоритм 2); `SearchResult`;
- `catalog/` — `Catalog` (агрегирует товары и модели, хранит в `Map`);
- корень пакета — `Main` (точка входа, тестовые данные).
